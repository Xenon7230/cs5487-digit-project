# CS5487 Course Project — A Comparative Study of Classical ML Methods for Handwritten Digit Classification

Group project for **CS5487 Machine Learning: Principles and Practice** (CityU).
Implements the course-defined two-trial evaluation protocol on the
**digits4000** dataset (4,000 handwritten digits, 10 classes, 784-dim
vectorized images, 400 per class).

Everything in this repository runs with real data: every number, CSV and PNG
is generated by code, nothing is hand-crafted.

## Research questions

- **RQ1** — How do classical classifiers differ in accuracy and error
  patterns on digits written by held-out writers?
- **RQ2** — How does PCA dimensionality reduction affect accuracy and
  computation cost?

## Methods (the "3+1" design)

**Experiment A — classifier benchmark (both trials):**

| config id | method | parameters |
|---|---|---|
| `knn_1` | Euclidean 1-NN | fixed (matches instructor baseline) |
| `logreg` | Logistic Regression, L2 | `C` ∈ {0.1, 1, 10}, chosen by CV |
| `lda` | Shrinkage LDA | fixed (`solver='lsqr'`, `shrinkage='auto'`) |
| `svm_linear` | Linear SVM | `C` ∈ {0.1, 1, 10}, chosen by CV |
| `svm_rbf` | RBF SVM | `C` ∈ {0.1, 1, 10} × `gamma` ∈ {0.001, 0.01, 0.1}, chosen by CV |

**Experiment B — PCA dimensionality:** `Logistic Regression` and `RBF SVM`
only, with `n_components` ∈ {None (full 784), 50, 100, 200}. PCA lives
*inside* an sklearn `Pipeline` so each CV fold refits it on fold training
data only (no leakage). `PCA(svd_solver='auto', random_state=seed)`.

**Experiment C — parameter & error analysis:** RBF SVM training-set CV
heatmaps (never test-set tuning plots), 10×10 confusion matrices per trial,
up to 12 misclassified examples per trial, and the most frequent
true→predicted confusion pairs, all computed from actual predictions.

**+1 — protocol layer:** strict dataset validation (shapes, index ranges,
disjoint writer-separated splits, class balance) and a fixed inner-CV
protocol (`StratifiedKFold(n_splits=3, shuffle=True, random_state=42)`).

## Setup

Python ≥ 3.10. This project was developed and fully run with the local conda
environment `cs5487` (Python 3.11, scikit-learn 1.9.1). To install the
dependencies:

```bash
python -m pip install -r requirements.txt
```

## Data placement

Unzip `digits4000_txt.zip` (from the parent directory) so that the four files
(`digits4000_digits_vec.txt`, `digits4000_digits_labels.txt`,
`digits4000_trainset.txt`, `digits4000_testset.txt`) are under
`data/digits4000_txt/`:

```bash
# from inside cs5487-digit-project/
mkdir -p data && unzip ../digits4000_txt.zip -d data   # produces data/digits4000_txt/
```

The loader also accepts `--data-dir data` (finds the `digits4000_txt`
subdirectory) or an original `digits4000.mat` (optional, via scipy).

## Run

```bash
python -m pip install -r requirements.txt
python -m pytest -q
python -m digit_project.run --data-dir data/digits4000_txt --output-dir outputs
```

Optional CLI flags (all implemented): `--seed 42` (random seed for CV splits
and models), `--n-jobs 1` (GridSearchCV parallelism; default 1 keeps the
machine responsive). One full run takes roughly 10–15 minutes on a laptop CPU
(RBF SVM grids dominate).

## Outputs

Tables in `outputs/tables/`:

| file | content |
|---|---|
| `model_comparison_trials.csv` | per model × trial: accuracy, macro-F1, fit/predict time, best params |
| `model_comparison_summary.csv` | per model: two-trial means and trial difference |
| `pca_comparison_trials.csv` | LR / RBF SVM × {None, 50, 100, 200} × trial: accuracy, F1, cumulative explained variance, times |
| `cv_parameter_results.csv` | training-set CV scores of every tuned parameter combo |
| `error_summary.csv` | RBF SVM most-frequent true→predicted error pairs per trial |

Figures in `outputs/figures/`: model-comparison bar chart (with per-trial
points), PCA accuracy curve, PCA training-time curve, RBF SVM CV heatmaps,
two confusion matrices, two misclassified-example montages.

`outputs/run_metadata.json` records versions, seed, input-file SHA-256
fingerprints and run config for reproducibility;
`outputs/experiment_notes.md` lists the computed results with objective
observations.

## Evaluation protocol (strictly followed)

1. For each trial, **only** that trial's `trainset` rows are used for fitting
   and CV; the trial's `testset` is evaluated exactly once, at the end.
2. Trainset/testset files store 1-based MATLAB indices; the loader converts
   them to 0-based and validates disjointness, full coverage and class
   balance (the two trials are complementary halves, writer-separated per the
   course description).
3. Pixel scaling `X / 255` is deterministic (known fixed range), applied
   before splitting; every data-dependent transform (PCA) lives inside the CV
   pipeline.
4. Hyper-parameters are selected by `GridSearchCV(scoring='accuracy')` with
   the fixed 3-fold stratified CV on the training set; grids were fixed
   before any test evaluation. Test accuracy is never used for tuning or for
   "parameter optimization" plots.
5. The 1-NN baseline reproduces the instructor's numbers (91.35% / 91.85%),
   which is the sanity check for loading, indexing and label alignment.
   (Verified in `tests/test_data.py::test_real_data_baseline_reproduction`.)

## Known limitations (stated honestly)

- **No writer IDs in the data.** The provided files contain no per-sample
  writer identity, so the *inner* CV cannot be writer-grouped; only the two
  final train/test splits are writer-separated (as guaranteed by the course).
- **Limited hyper-parameter grids.** Grids were intentionally kept small
  (3–9 combos per model) to keep the project tractable; other choices may
  perform better.
- **Timing numbers are environment-relative.** Reported fit/predict times are
  wall-clock on the development machine and are only rough cost references.
- **Accuracy-axis zoom in figures.** Bar/line charts zoom the y-axis (floor
  0.80) because the models differ by a few points; values are always labeled
  directly on the marks.
- **PCA solver.** `svd_solver='auto'` (randomized for reduced dims) — a tiny
  approximation in explained-variance ratios, deterministic via
  `random_state`.
- Data-driven preprocessing beyond PCA (e.g. `StandardScaler`) was not
  included as a separate arm by design.
